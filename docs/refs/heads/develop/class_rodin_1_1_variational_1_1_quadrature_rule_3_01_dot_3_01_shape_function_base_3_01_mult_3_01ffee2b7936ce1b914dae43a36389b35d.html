Architecture

Mapped quadrature samples and the completed local matrix are owned by the rule. Reference tables are borrowed only during binding, after the current coefficient value has been materialized. Public entry access retains test rows and trial columns independently of the private storage order.

Scalar coefficients

A scalar coefficient gives . For left scaling, row-major addresses of successive matching components differ by , where counts trial DOFs, including for rectangular mixed-degree operators. Scalar fields have by their range type and update directly, without runtime component traversal. Right scaling uses trial-major traversal and column-major storage, with matching-component stride , where counts test DOFs. For aggregate ranges, real storage uses the corresponding integer stride; complex storage retains explicit row/column addressing. The public entry convention remains test rows and trial columns, including mixed degrees. Matrix-valued coefficients remain coupled and do not use this component diagonal structure. Scalar right scaling retains the expression . Its contribution is evaluated in the original order , not by commuting or regrouping the coefficient. Right-side reference values retain the finite-element scalar type before coefficient promotion. Coefficients are evaluated before either reference table is borrowed. Each scaled right-side trial value is reused across the test bases at the current sample. Fixed one-element views use the existing dot product without constructing component-expanded values. The complex weighted contribution is formed once before component replication. Real multiplication remains in the entry update to preserve the established floating-point association. Quadrature accumulation order is unchanged, and no additional persistent cache or assembly-backend condition is introduced. Right-scaled scalar fields retain generic cached-trial quadrature; this component rule accepts right scaling only for vector and matrix carriers.
