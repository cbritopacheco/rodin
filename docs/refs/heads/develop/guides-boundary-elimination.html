This reference expands the algebraic step introduced in the boundary conditions guide. It is intended for callers supplying their own sparse operators and for assembly developers.

Math::LinearSystem also accepts an arbitrary caller-supplied square CSC operator. Essential elimination supports nonsymmetric coefficients, asymmetric sparse patterns and missing constrained diagonals. Duplicate triplets must first be assembled into valid sorted, unique-row sparse storage, as with Eigen's setFromTriplets.

Sparse implementation

The operation validates the system dimensions and shifted constraint indices before mutation, then compresses the operator. It traverses every constrained column of the original matrix to accumulate the load lifting, recording its diagonal position after the traversal. Only after all lifting is complete may an absent diagonal be inserted. Missing diagonals are merged together into the existing CSC arrays by moving entries backwards, avoiding repeated shifts or a full matrix copy. Existing entries and explicit zeros are retained.

A temporary byte mask identifies constrained rows. Consecutive constrained columns are cleared in coalesced storage ranges. Free storage between them is examined in blocks. An empty row mask performs no coefficient stores, while a nonempty mask visits only its set bits. The final scalar tail follows the same zeroing rule. Actual zero assignment or bit clearing is required because multiplication by zero would retain NaNs or create them from infinities. Constraint diagonals and prescribed load entries are restored last.

A single contiguous constraint interval can select sorted row-range pruning. The selection uses sixteen samples at equal stored-entry quantiles, requires at least eight stored entries per column on average, and requires at least half the usable samples to reject the interval. These measured heuristics select the clearing kernel; the column bounds certify each omitted interval. Partial overlaps use binary searches to locate the constrained coefficient range. Fragmented constraints retain the block kernel. No particular FEM boundary numbering is assumed.

For rows, stored entries and constraints, block clearing and batch insertion require work and temporary storage. Pruning adds up to two binary searches per overlapping free column. Operator storage grows only for absent constrained diagonals. It remains compressed, with sorted row indices, after the call. The solution vector is untouched, preserving warm starts. Repeating the same constraints is idempotent up to floating-point rounding. An empty constraint map only validates dimensions and compresses storage.

This algorithm is serial and constructs no persistent transpose index or parallel worker pool. The linear scan visits stored entries once while clearing the constrained rows and columns. Tests compare the matrix and load against independent projector constructions, including asymmetric storage, missing diagonals, complex data, offsets and mixed finite-element systems. The opt-in RodinSparseEliminationBenchmarks executable measures the public operation with restoration outside timing.
