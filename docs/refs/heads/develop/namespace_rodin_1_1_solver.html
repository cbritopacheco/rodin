Rodin::Solver module

Solution of linear and nonlinear discrete systems.

Contents

  • Reference
    • Classes
    • Enums
    • Functions
    • Variables

CG handles symmetric positive-definite systems, GMRES handles general iterative solves, and SparseLU provides direct sparse factorization. NewtonSolver drives nonlinear solves. These solvers operate on prepared systems or variational problems and provide convergence controls for PDE and optimization calculations.

Direct solvers (exact up to floating-point precision):

  • SparseLU — General-purpose sparse LU factorization
  • UMFPack — SuiteSparse UMFPACK solver
  • CHOLMOD — SuiteSparse Cholesky for SPD systems
  • SimplicialLLT — Simplicial
  • SimplicialLDLT — Simplicial
  • SparseQR — Sparse QR factorization
  • SPQR — SuiteSparse sparse QR
  • HouseholderQR — Dense Householder QR
  • LDLT — Dense

Iterative solvers (for large systems):

  • CG — Conjugate Gradient (SPD systems)
  • BiCGSTAB — Bi-conjugate gradient stabilized
  • GMRES — Generalized Minimum Residual
  • DGMRES — Deflated GMRES
  • MINRES — Minimum Residual (symmetric systems)
  • IDRS — Induced Dimension Reduction
  • IDRSTABL — IDR(s) with stabilization
  • LeastSquaresCG — Least-squares CG

A solver can be constructed from an assembled form or problem.

// Inline iterative solver — most common pattern
Solver::CG(problem).solve();

// Configured iterative solver
Solver::CG solver(problem);
solver.setMaxIterations(1000);
solver.setTolerance(1e-10);
solver.solve();

// Direct solver
Solver::SparseLU(problem).solve();

Nonlinear solvers (for hyperelastic or other nonlinear problems):

  • Solver::NewtonSolver<LinearSolver> — Newton-Raphson iteration for nonlinear variational problems. At each iterate , assembles the tangent system and updates . Configurable via setMaxIterations(), setAbsoluteTolerance(), and setRelativeTolerance().

Enum documentation

enum class Rodin::Solver::Factorization

Defined in Rodin/Solver/Info.h

Stage of a factorization.

Symbolic analysis depends only on the sparsity pattern, whereas the numeric factorization also depends on the values. A solver that retains Factorization::Numeric therefore retains Factorization::Symbolic too.
